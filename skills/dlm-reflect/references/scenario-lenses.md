# Scenario Lenses

不要机械把所有场景都列一遍。只选择能证实/证伪 Frozen 条件或防止具体实质风险的 lens; 不设置固定数量。

## 选择规则

- Frozen 条件只涉及合同/文档且无运行声明时, 不强制运行场景 lens。
- 若完成声明涉及状态、生命周期、共享资源或外部依赖, 选择最可能改变结论的相关 lens。
- 局部 patch 可优先考虑顺序错位、重复执行、依赖异常, 但只有适用条件或具体风险需要时才成为验收项。
- 未被 Frozen 基线或实质安全边界采用的发现只作 Advisory, 不静默增加完成条件。

## 通用 Lens

### 1. Empty / Default

问:

- 空输入、缺省配置、空集合、未初始化状态是否成立
- 第一次进入系统或第一次调用时是否成立

### 2. Invalid / Exceptional

问:

- 非法参数、格式错误、脏数据、缺失依赖时是否成立
- 当前改动是否只是把异常路径推迟到更深层才爆炸

### 3. State Transition

问:

- 从 A 到 B, 再从 B 回 A 是否成立
- 状态切换中间有没有脏状态或遗留副作用

### 4. Re-entry / Repeat

问:

- 连续执行两次、重复提交、重复加载、重复初始化是否稳定
- 上次执行的残留是否会污染下次结果

### 5. Ordering / Timing

问:

- 调用顺序变化、操作顺序变化、事件先后错位时是否成立
- 当前方案是否依赖一个“理想顺序”但未显式防护

### 6. Dependency Failure

问:

- 上游缺席、下游失败、超时、返回异常时是否成立
- 当前模块是否把外部失败误当作内部完成

### 7. Lifecycle / Resource

问:

- 创建、使用、释放、销毁的完整过程是否自洽
- 资源、句柄、订阅、缓存、文件、连接是否留脏

### 8. Concurrency / Shared State

问:

- 并发访问、共享状态、多 worker、重复 claim 时是否成立
- 当前实现是否引入了新的竞态窗口

## 技术栈映射示例

- Web/UI: 空态、误操作、交互顺序、状态同步、重绘后状态保持
- Backend/API: 幂等、事务、回滚、错误传播、兼容性
- Native/System: 生命周期、资源释放、线程切换、宿主交互
- Plugin/Extension: 宿主隔离、契约稳定性、注册/卸载、能力边界
- Data/Script: 重跑、副作用、批次顺序、恢复能力、脏输入
- Doc/Workflow: 事实缺漏、协议漂移、跨文档一致性、状态同步
