# Grilling Protocol

把 `grill-me` 的连续追问能力用于方案锐化和执行后复检。目标不是让对话变激烈或制造更多审查意见, 而是用与声明适配的证据检验会改变当前决定的薄弱前提。不得借追问静默增加用户目标、适用合同、已接受约束和实质安全边界之外的完成条件。

## 1. 选择 Claim 类型

- `design`: 将要执行的需求、计划、产品方案或技术设计
- `closure`: 已完成实现的闭环声明

`design` 重点追问:

- 谁的问题、期望结果和非目标是否明确
- 关键约束、依赖和不可逆决策是否暴露
- 为什么选择当前方案, 替代方案为何不选
- 失败模式、安全边界、成本与维护责任是否可接受
- 成功标准是否可观察、可测试、可判定

`closure` 重点追问目标行为、真实证据、反例、范围边界、恢复路径和局部到整体的推论。

## 2. 建立可被推翻的声明

先用一句话写出当前声明, 例如:

> 选择方案 X 可以在约束 C 下实现目标 A, 因此已可进入正式规划。

或:

> 当前 Subtask 已满足 A、B、C, 因此可以结束并进入 sediment。

再把它拆成会影响 routing 的最小充分关键前提。优先覆盖:

- 对 `design`, 关键前提应覆盖用户结果、约束、替代方案、失败边界和可验证成功标准
- 对 `closure`, 关键前提应覆盖真实行为、目标运行面证据、非主路径反例、diff 范围、恢复路径和局部到整体的推论

不要为了凑数量提出低价值问题。行政记录、展示完整度或审查偏好只有在真实消费者或当前决定依赖时才进入关键前提。

## 3. 从最薄弱前提开始追问

一次只处理一个最可能改变结论的问题:

1. 写出问题。
2. 先从 diff、测试、日志、产物和运行观察中自行回答。
3. 主动寻找反例, 不只寻找支持材料。
4. 将前提标记为:
   - `proven`: 直接证据足以支撑
   - `disproven`: 已有反例或证据与声明冲突
   - `unknown`: 证据缺失、间接或不可区分
5. 若为 `unknown`, 给出能让它变为 `proven` 或 `disproven` 的最小补证动作。

处理完当前问题后, 重新选择剩余前提中最薄弱的一条, 不要照固定问卷机械推进。

## 4. 证据优先于访谈

- 能通过本地只读检查、现有测试或任务范围内的安全验证回答时, 直接查证。
- 只有当缺失的是用户专属目标、验收取舍、外部事实或新增授权时, 才向用户提问。
- 向用户提问时每次只问一个会改变 routing 的问题, 并说明当前证据为何无法替代该答案。
- 在 `design` 模式中, 用户的业务取舍本身可以锁定决策, 但不能替代技术可行性证据。
- 在 `closure` 模式中, 用户的主观确认不能替代本应存在的技术证据; “我觉得可以”不能把 `unknown` 自动改成 `proven`。
- 跨层证据只有在能说明为何足以支持当前决定时才可使用; 任务索引、hash 或绿色检查不能默认代替运行/合同证据。

## 5. 重点识别错误等价

遇到下列推论时必须追问:

- 计划完成 = 实现完成
- 文档或矩阵完成 = 真实验收完成
- 构建通过 = 运行行为正确
- 单元测试通过 = 集成链路正确
- 代表样例通过 = 全量对象通过
- 局部 work item 完成 = Epic 完成
- 没观察到错误 = 已证明没有错误

## 6. 停止条件

满足任一条件时停止追问并进入 routing:

- 所有关键前提均为 `proven`, 且没有未解释的高风险反例。
- 任一关键前提为 `disproven`, 已足以判定继续当前任务、实现偏移或回规划。
- 关键前提仍为 `unknown`, 但最小补证动作已明确且当前无法执行; 判定部分完成或 blocked。
- 剩余问题只影响低风险偏好, 不改变任务闭合性或 sediment 门禁。
- 对 `design`, 目标、边界、关键取舍和成功标准已经清晰到足以进入 `dlm-plan`。
- 对 `closure`, Frozen 条件和必需证据均成立且到达停止线; 剩余内容只有 Advisory 或无当前消费者的行政同步。

禁止因为“已经问了很多”而停止, 也禁止在结论已经足够明确后继续消耗式追问。同一稳定目标状态完成一次正式全量审计后, 修正只复验原 FAIL 与直接回归。

## 7. 输出压缩

`Design Grill Verdict` 只保留已锁定决策、被修正假设、剩余未知项、成功标准和路由。

`Closure Review` 中只保留会影响结论的内容:

- `完成声明`
- `最薄弱前提`
- `proven / disproven / unknown` 摘要
- `关键反例或补证动作`
- `Grilling 结论`

若没有需要用户回答的问题, 不要为了展示过程而输出整段访谈记录。
